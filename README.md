# O2Ban Pilot v1.2 — Controlled Procurement Trial

**نسخه مستقل اعتبارسنجی محصول O2Ban برای مدیریت تدارکات و زنجیره تأمین سازمانی**

این نرم‌افزار یک نمونه مستقل و چندصنعتی برای ارزیابی گردش کار نیاز خرید، جست‌وجوی تأمین‌کننده، دریافت و مقایسه پیشنهادها، مدیریت شواهد، سفارش، تحویل و ارزیابی عملکرد است. این محصول به هیچ شرکت، صنعت یا سامانه سازمانی مشخصی وابسته نیست.

## مرزبندی و حاکمیت استفاده
- این مخزن برای توسعه و اعتبارسنجی محصول مستقل O2Ban تهیه شده است و نباید به‌عنوان نرم‌افزار رسمی یا متعلق به محل اشتغال توسعه‌دهندگان معرفی شود.
- داده‌های Seed داخل برنامه کاملاً ساختگی و صرفاً برای نمایش قابلیت‌ها هستند.
- اطلاعات محرمانه، اسناد داخلی، فهرست تأمین‌کنندگان، قیمت‌ها، قراردادها، اطلاعات کارکنان، داده‌های خرید یا هر دارایی متعلق به کارفرما را وارد نکنید.
- هیچ اتصال آماده‌ای به SAP، ERP، شبکه داخلی، پایگاه داده یا API سازمانی وجود ندارد. هرگونه استفاده از زیرساخت، تجهیزات، زمان کاری، حساب کاربری، شبکه یا محیط سازمانی برای اجرای آزمایش، نیازمند مجوز کتبی و تعیین روشن مالکیت فکری، مسئولیت امنیت، محدوده دسترسی و حق استفاده از نتایج است.
- برای آزمون در محیط سازمانی، از نمونه‌داده ساختگی یا داده‌ای استفاده کنید که مجوز مستقل و صریح استفاده از آن را دارید. اجرای پایلوت در محل کار به‌خودی‌خود مجوز استفاده از داده‌ها یا منابع شرکت نیست.

## وضعیت انتشار v1.2
- حذف حساب‌های پیش‌فرض و ایجاد مدیر اولیه فقط با اسرار محیطی.
- غیرفعال‌سازی ثبت‌نام عمومی و افزودن مدیریت کاربران توسط مدیر.
- جلوگیری از تأیید فنی پیشنهاد توسط ثبت‌کننده پیشنهاد؛ بررسی فنی فقط توسط مدیر مجاز.
- اصلاح مقایسه: پیشنهاد رد فنی یا خارج از موعد، امتیاز قیمت/تحویل نمی‌گیرد.
- افزودن Dockerfile و Compose برای استقرار پشت Reverse Proxy و TLS.
- این نسخه هنوز قبل از انتشار نیازمند Build و آزمون اجرایی روی سرور مقصد است.

## فناوری‌ها
- .NET 10 / ASP.NET Core MVC / Razor
- C# و Entity Framework Core 10
- MariaDB 11.4 LTS
- `Microting.EntityFrameworkCore.MySql` 10.0.14؛ Provider سازگار با EF Core 10 و مبتنی بر خانواده Pomelo
- ASP.NET Core Identity و نقش‌های Admin / Procurement
- موتور جست‌وجوی تطبیق محلی و قاعده‌محور (بدون اتصال به LLM بیرونی)

> نکته سازگاری: Provider رسمی Pomelo در شاخه 9.x به EF Core 9 وابسته است؛ برای حفظ .NET 10 و EF Core 10، این نسخه از شاخه Microting استفاده می‌کند که برای MariaDB 11.4 نیز در ماتریس آزمون خود پشتیبانی اعلام کرده است. این Provider فورک جامعه‌محور است، نه بسته رسمی Pomelo یا Microsoft. پیش از ارتقای بعدی نسخه Provider و EF Core باید با هم بررسی شوند.

## پیش‌نیازها و اجرا
1. نصب .NET 10 SDK و Docker Desktop / Docker Engine.
2. از پوشه پروژه، فایل تنظیمات محیطی را ایجاد کنید:
   ```bash
   cp .env.example .env
   ```
   در ویندوز PowerShell:
   ```powershell
   Copy-Item .env.example .env
   ```
3. در فایل `.env`، مقادیر `MARIADB_ROOT_PASSWORD`، `MARIADB_PASSWORD` و `O2BAN_BOOTSTRAP_ADMIN_PASSWORD` را با گذرواژه‌های قوی و منحصربه‌فرد جایگزین کنید. از گذرواژه‌های نمونه استفاده نکنید.
4. اجرای محلی با Docker Compose:
   ```bash
   docker compose up -d --wait
   ```
   برنامه روی `http://localhost:8080` در دسترس است. برای اجرای برنامه خارج از Docker، MariaDB را با `docker compose up -d --wait mariadb` بالا بیاورید و Connection String را از طریق متغیر محیطی `ConnectionStrings__DefaultConnection` تنظیم کنید. فرمت آن:
   ```text
   Server=127.0.0.1;Port=3306;Database=o2ban_enterprise_validation;User=o2ban_app;Password=YOUR_PASSWORD;CharSet=utf8mb4;SslMode=Preferred
   ```
5. در اولین اجرا، برنامه با `EnsureCreated()` ساختار دیتابیس خالی را ایجاد می‌کند؛ داده‌های نمایشی فقط در Development یا با تنظیم صریح `O2BAN_SEED_DEMO_DATA=true` بارگذاری می‌شوند.

### نکات مهم دیتابیس
- نسخه Docker پیش‌فرض MariaDB برابر 11.4 LTS است.
- پورت دیتابیس فقط روی `127.0.0.1:3306` منتشر می‌شود و به‌صورت پیش‌فرض از شبکه عمومی قابل دسترسی نیست.
- داده‌های دیتابیس در Volume به نام `o2ban_mariadb_data` نگهداری می‌شوند؛ حذف کانتینر به‌تنهایی داده‌ها را حذف نمی‌کند.
- برای توقف MariaDB بدون حذف داده‌ها: `docker compose down`.
- برای حذف کامل داده‌های محلی، فقط در صورت اطمینان از داشتن نسخه پشتیبان: `docker compose down -v`.
- فایل `.env` حاوی گذرواژه است و نباید در Git یا برای دیگران ارسال شود.

## حساب‌های کاربری و راه‌اندازی امن
- هیچ حساب مدیر یا کاربر با گذرواژه ثابت داخل سورس ایجاد نمی‌شود.
- در Production، حساب مدیر اولیه فقط از طریق متغیرهای محیطی `O2BAN_BOOTSTRAP_ADMIN_EMAIL` و `O2BAN_BOOTSTRAP_ADMIN_PASSWORD` ساخته می‌شود.
- ثبت‌نام عمومی غیرفعال است؛ مدیر از بخش «مدیریت کاربران» حساب‌های کارشناسان را ایجاد می‌کند.
- گذرواژه مدیر اولیه را پس از اولین ورود از تنظیمات حساب تغییر دهید و دسترسی به متغیرهای محیطی سرور را محدود کنید.
- داده‌های نمایشی فقط در Development یا در صورت تنظیم `O2BAN_SEED_DEMO_DATA=true` بارگذاری می‌شوند. در Production مقدار آن را `false` نگه دارید.

## استقرار روی سرور
برای مراحل استقرار با Dockerfile، تنظیم دامنه و نگهداری فایل‌ها در Coolify، راهنمای [استقرار در Coolify](COOLIFY_DEPLOYMENT_FA.md) را ببینید. استقرار Coolify از `Dockerfile` ریشه استفاده می‌کند و مقدار Connection String را از `appsettings.json` همین مخزن می‌خواند؛ دسترسی شبکه‌ای سرور Coolify به دیتابیس پیکربندی‌شده باید برقرار باشد.

**محدودیت دامنه این نسخه:** این انتشار برای یک سازمان/یک تیم پایلوت در یک استقرار مستقل طراحی شده است. جداسازی چندمستاجری (Multi-Tenant) بین چند شرکت هنوز پیاده‌سازی نشده؛ بنابراین این نسخه را به چند سازمان مستقل یا کاربران بیرونی از سازمان پایلوت ارائه نکنید. استفاده فقط با داده ساختگی یا داده‌ای که مجوز روشن و مکتوب برای آن وجود دارد مجاز است.

## قابلیت‌های موجود
- داشبورد اعتبارسنجی محصول و شاخص‌های پایه
- کاتالوگ عمومی کالاها و اقلام با کد، دسته‌بندی و حوزه کاربرد
- مدیریت تأمین‌کنندگان و وضعیت شواهد
- ثبت درخواست خرید و پیشنهادهای نسخه‌بندی‌شده
- تأیید/رد فنی پیشنهاد فقط توسط مدیر مجاز؛ ثبت پیشنهاد به‌تنهایی به معنی تأیید فنی نیست
- جست‌وجوی متنی تأمین‌کننده با نمایش دلایل تطبیق و شکاف‌های داده
- مقایسه پیشنهادها با نمایش تفکیک‌شده معیارها
- مدیریت شواهد و مستندات
- تبدیل پیشنهاد معتبر و تأییدشده به سفارش آزمایشی
- ثبت تحویل، مقادیر پذیرفته/مردود و ارزیابی عملکرد تأمین‌کننده
- ثبت بازخورد کاربران و گزارش‌های اعتبارسنجی

## محدودیت‌های فنی فعلی
- موتور جست‌وجو محلی و قاعده‌محور است؛ امتیاز ارتباط متنی، تأیید فنی یا اعتبارسنجی قطعی تأمین‌کننده نیست.
- فرایندها برای پایلوت محدود طراحی شده‌اند؛ قبل از انتشار باید Build، تست امنیتی، تست دسترسی، تست محاسبات، تست فایل و تست بار در محیط مقصد اجرا شوند.
- ذخیره فایل شواهد محلی است؛ برای استقرار چندنمونه‌ای به ذخیره‌ساز مشترک امن و سیاست پشتیبان‌گیری نیاز است.
- نسخه فعلی همچنان از `EnsureCreated()` برای ساخت دیتابیس تازه و خالی استفاده می‌کند؛ EF Core Migrations هنوز در این بسته تولید نشده است. پیش از انتشارهای بعدی باید Migrationهای نسخه‌بندی‌شده و برنامه بازگشت پیاده‌سازی شوند.
- `EnsureCreated()` دیتابیس SQL Server موجود را به MariaDB تبدیل نمی‌کند و داده‌ها را انتقال نمی‌دهد. در ZIP ارسالی فایل دیتابیس SQL Server وجود نداشت؛ بنابراین این نسخه برای ایجاد دیتابیس MariaDB تازه آماده شده است. اگر دیتابیس SQL Server جداگانه‌ای دارید، باید آن را با فرآیند ETL/Export-Import و نگاشت نوع داده‌ها منتقل و جداگانه اعتبارسنجی کنید.
- محاسبه ROI و صرفه‌جویی واقعی نیازمند تعریف خط مبنا و ثبت رویدادهای معتبر است؛ گزارش فعلی به‌تنهایی اثبات‌کننده ارزش اقتصادی نیست.

## چک‌لیست پیش از هر پایلوت
1. تعیین مالک محصول، مالکیت فکری کد و مجوز استفاده از محیط اجرا به‌صورت مکتوب.
2. تأیید کتبی محدوده آزمایش، کاربران مجاز، مدت اجرا و مسئولیت امنیت.
3. استفاده انحصاری از داده‌های ساختگی یا داده‌های دارای مجوز روشن؛ عدم ورود هرگونه داده محرمانه یا دارایی کارفرما.
4. جداسازی حساب‌ها، دستگاه‌ها، مخازن کد، پایگاه داده و فایل‌های محصول از سامانه‌های کارفرما.
5. تغییر گذرواژه‌های پیش‌فرض، تنظیم HTTPS، مدیریت اسرار، پشتیبان‌گیری و کنترل دسترسی.
6. تعریف شاخص‌های قبل و بعد: زمان چرخه، زمان یافتن تأمین‌کننده، تعداد پیشنهادهای قابل‌مقایسه، کامل‌بودن شواهد، نرخ پاسخ و رضایت کاربر.
7. ثبت رضایت کاربران و مستندسازی نتایج بدون جمع‌آوری اطلاعات غیرضروری.

## ساختار کلی
- `Controllers`: کنترلرهای گردش کار
- `Models`: مدل‌های دامنه و ViewModelها
- `Data`: DbContext و داده‌های نمایشی
- `Services`: موتورهای جست‌وجو، مقایسه و ارزیابی
- `Views`: رابط کاربری فارسی و راست‌چین

**وضعیت این بازبینی:** خطاهای Razor و وابستگی UI مربوط به ASP.NET Identity اصلاح شده‌اند. Build محلی با .NET 10 اجرا می‌شود؛ اجرای image و MariaDB به Docker Engine در دسترس نیاز دارد.
